# Правила написания кода

## Язык

- **Идентификаторы — по-английски**, по словарю [glossary.md](glossary.md).
- **Комментарии — по-русски**, коротко. Комментарий объясняет *почему*, а не *что*. Если правило пришло из дизайна, ссылаться на файл: `// см. docs/06-time-system.md, правило 1`.
- Строки для игрока и журнала (`name: 'Пламя'`) — по-русски.

## TypeScript

- `strict: true`, плюс `noUncheckedIndexedAccess: true`, `exactOptionalPropertyTypes: true`.
- Никаких `any`. Если тип неизвестен — `unknown` и сужение.
- Никаких `enum` — использовать `as const` объекты и объединения строковых литералов.
- Предпочитать `interface` для объектов данных, `type` — для объединений.
- Именованные экспорты, без `export default`.
- Единицы измерения — в имени или типе: `durationSec`, `rangeUnits`, тип `Seconds = number`.

## Правила ядра (`packages/core`)

Эти правила нельзя нарушать: от них зависят сервер, реплеи и боты.

1. **Без окружения.** Запрещено: DOM, `window`, `process`, `fs`, `setTimeout`, `setInterval`, сетевые вызовы.
2. **Детерминизм.**
   - Запрещено `Math.random()` — только `world.rng`.
   - Запрещено `Date.now()`, `performance.now()` — только `world.tick` и локальные часы.
   - Перебор сущностей — в стабильном порядке (по `id`), не полагаться на порядок вставки в `Set` из разных источников.
3. **Время — только локальное.** Любой таймер сущности уменьшается на её `localDt`. Никаких «сработать на тике N».
4. **Изменения — через API.** Состояния меняются только функциями `core`, которые пишут событие в журнал. Прямое присваивание полей состояния вне `core` — запрещено.
5. **Без исключений по идентичности.** Код системы или закона не может проверять «это Хронист?» или «это закон L7-01?». Только метки и состояния. Единственное место для явных особых взаимодействий — `content/interactions.ts`.

## Правила содержимого (`packages/content`)

- Один закон — один файл в `content/laws/`. Вверху файла — комментарий со ссылкой на запись в каталоге: `// docs/04-laws-catalog.md, L3-01`.
- Числа (урон, длительность, радиус) — в `params` закона, не разбросаны по коду.
- Герой — один файл в `content/heroes/` (этап 2+).

## Стиль

- Форматирование — Biome, по умолчанию. Перед коммитом: `pnpm lint`.
- Функции короткие. Система длиннее ~150 строк — разбить.
- Мутации данных разрешены (это симуляция, не React), но только внутри систем и API `core`.
- Не добавлять зависимостей без записи в [decisions.md](decisions.md).

## Когда дизайн неясен

1. Найти ответ в `docs/`.
2. Не нашёл — выбрать самый лорно-честный вариант (см. [../01-lore-integrity.md](../01-lore-integrity.md)), реализовать и записать допущение в [decisions.md](decisions.md) с пометкой `ДОПУЩЕНИЕ`.
3. Никогда не нарушать принцип лорной честности ради простоты кода.
