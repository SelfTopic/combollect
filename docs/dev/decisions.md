# Журнал решений

Новые записи — сверху. Формат:

```
## <номер>. <Название> — <ГГГГ-ММ-ДД>
Тип: РЕШЕНИЕ | ДОПУЩЕНИЕ
Контекст: почему понадобилось
Решение: что выбрали
Альтернативы: что ещё рассматривали (коротко)
```

`ДОПУЩЕНИЕ` — решение о дизайне игры, принятое без автора. Автор их проверяет и либо утверждает, либо меняет.

## 5. Инструменты этапа 1 и проверка чистоты ядра — 2026-10-29
Тип: РЕШЕНИЕ
Контекст: каркас репозитория по [stack.md](stack.md) и [stage-1.md](stage-1.md).
Решение: TypeScript 5.9, Vitest 5, Biome 2, tsx; `@types/node` только для `tools/sim` и корневых тестов. Пакеты не собираются: `exports` указывают прямо на `.ts`-исходники. У `core` и `content` в `tsconfig` нет типов DOM и Node — обращение к окружению просто не скомпилируется. Дополнительно Biome запрещает в ядре `Date`, `process`, `setTimeout` и т. п., а тест `test/core-purity.test.ts` ищет в исходниках ядра `Math.random`, `Date.now` и импорты Node. Biome не трогает `.md` (иначе он переформатирует дизайн-документы). В `engines` указан Node ≥ 22: в облачной сессии стоит Node 22, у автора Node 24 — оба подходят.
Альтернативы: собирать пакеты в `dist` (лишний шаг без пользы на этапе 1).

## 4. Фиксированный тик 30 в секунду — 2026-10-29
Тип: РЕШЕНИЕ
Контекст: нужен детерминированный шаг симуляции для сервера, реплеев и ботов.
Решение: `WORLD_DT = 1/30`. Клиент (этап 2+) интерполирует отрисовку между тиками.
Альтернативы: 20 тиков (грубее), 60 (дороже для сервера).

## 3. Часы у каждой сущности с первого дня — 2026-10-29
Тип: РЕШЕНИЕ
Контекст: законы времени ([../06-time-system.md](../06-time-system.md)) нельзя добавить потом, не переписав все таймеры.
Решение: у каждой сущности `clock.rate`; все таймеры — в локальном времени.

## 2. Монорепозиторий на pnpm: core, content, tools/sim — 2026-10-29
Тип: РЕШЕНИЕ
Контекст: одно ядро должно работать в браузере, на сервере, в ботах и тестах.
Решение: `packages/core` без зависимостей от окружения, `packages/content` с законами, `tools/sim` для запуска сценариев.

## 1. TypeScript, браузер сначала, exe позже — 2026-10-29
Тип: РЕШЕНИЕ
Контекст: автор хочет играть с другом по ссылке, а позже выпустить исполняемый файл.
Решение: TypeScript; клиент в браузере (Vite + PixiJS, этап 2); exe через Tauri при выпуске.
Альтернативы: Godot (экспорт в оба формата, но ядро не разделить с сервером и ботами так же просто), Rust + WebAssembly (сложнее и дольше).
