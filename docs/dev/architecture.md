# Архитектура

## Главный принцип

**Код повторяет устройство мира из дизайна.** Метки, состояния, законы, часы, следы на карте — это прямые сущности в коде. Если в коде появляется что-то, чего нет в дизайне (например, «оглушение» как отдельный флаг), значит, что-то пошло не так: см. [../01-lore-integrity.md](../01-lore-integrity.md).

## Пакеты

```
combollect/
├── packages/
│   ├── core/        # движок мира: сущности, метки, состояния, часы, карта, системы, API законов
│   └── content/     # содержимое: конкретные законы, герои, объекты карты (используют API core)
├── tools/
│   └── sim/         # CLI: запуск сценария без графики, вывод журнала событий
├── apps/            # этап 2+: client (браузер), server
└── docs/
```

Зависимости строго в одну сторону: `content → core`, `tools/sim → content, core`. `core` не знает ни об одном конкретном законе.

## Мир (`World`)

Мир — это всё состояние симуляции. Он сериализуем в JSON (для сети, реплеев и тестов).

```ts
interface World {
  tick: number;            // номер тика мира
  rng: Rng;                // единственный источник случайности, с сидом
  entities: Map<EntityId, Entity>;
  grid: Grid;              // клетки карты
  timeFields: TimeField[]; // активные изменения течения времени
  events: EventLog;        // журнал всего, что произошло (для отладки и «объяснимого проигрыша»)
}
```

## Сущность (`Entity`)

Три вида атомов из [../02-atoms.md](../02-atoms.md):

```ts
interface Entity {
  id: EntityId;
  tags: Set<TagId>;        // метки: что сущность ЕСТЬ
  state: EntityState;      // состояния: что с ней СЕЙЧАС (температура, влажность, зоны тела, ...)
  resources: Resources;    // здоровье, лорный ресурс
  position: Vec2;
  velocity: Vec2;
  clock: Clock;            // свои часы, см. ниже
  laws: LawSlot[];         // законы, которыми владеет (с прокачкой и перезарядкой)
  plan: PlannedAction[];   // запланированные действия, см. ../06-time-system.md
}
```

Метки — строки из реестра (`'Living'`, `'Trauma:Loss'`, `'OutOfTime'`). Состояния — типизированные поля, а не произвольный словарь.

## Часы (`Clock`)

См. [../06-time-system.md](../06-time-system.md). Это архитектурное решение номер один.

- Мир тикает с фиксированным шагом: **30 тиков в секунду**, `WORLD_DT = 1/30`.
- У каждой сущности `clock.rate` (по умолчанию 1). `localDt = WORLD_DT * rate`.
- `rate` вычисляется каждый тик из активных `TimeField`: множители перемножаются; сущности с меткой `OutOfTime` игнорируют поля других носителей.
- **Все таймеры хранятся в локальном времени сущности** (оставшиеся секунды, которые уменьшаются на `localDt`), никогда не в абсолютных тиках мира. Иначе остановка времени сломает таймеры.
- Длительность самого `TimeField` считается в часах его носителя.

## Системы

Каждый тик системы выполняются **в фиксированном порядке**. Каждая система — чистая функция `(world) => void`, которая меняет мир только через API `core`.

Порядок (этап 1):
1. `clockSystem` — пересчитать `rate` всех сущностей
2. `planSystem` — выполнить запланированные действия, если сущность может действовать
3. `lawSystem` — подготовка, применение и перезарядка законов
4. `movementSystem` — движение и столкновения (учитывая массу, лёд)
5. `projectileSystem` — полёт снарядов и попадания
6. `thermalSystem` — температура, горение, распространение огня, таяние и замерзание
7. `wetnessSystem` — влажность сущностей и клеток
8. `conductionSystem` — распространение тока по графу проводников
9. `bodySystem` — зоны тела, их последствия (скорость, атака)
10. `traceSystem` — следы на карте и их угасание
11. `deathSystem` — смерть, удаление сущностей

Добавлять систему — с записью в [decisions.md](decisions.md), если меняется порядок.

## Законы (`Law`)

Закон — это **данные + обработчик**. Данные повторяют шаблон из [../04-laws-catalog.md](../04-laws-catalog.md).

```ts
interface LawDef {
  id: LawId;               // 'L3-01'
  name: string;            // 'Пламя' — для журнала и интерфейса
  tier: Tier;              // 0..7
  requires: TagQuery;      // на кого действует
  excludes: TagQuery;      // кто иммунен
  form: LawForm;           // точка, луч, зона, глобально, снаряд, ...
  windup: Seconds;         // подготовка
  cooldown: Seconds;
  cost: Cost;              // ресурс + лорная цена
  params: Record<string, number>; // прокачиваемые параметры
  apply(ctx: LawContext): void;   // что делает
}
```

Правила для законов:
- **Закон меняет только состояния и ресурсы** через API (`ctx.changeTemperature(target, +15)`), а не пишет поля напрямую. API записывает событие в журнал с причиной.
- **Закон не знает о других законах.** Взаимодействия получаются через общие состояния (температура, влажность, проводимость, часы). Это «системные» взаимодействия из [../05-interactions.md](../05-interactions.md).
- **Особые взаимодействия** (их мало) регистрируются явно в одном месте: `content/interactions.ts`, каждое со ссылкой на строку таблицы в дизайне.
- **Закон по умолчанию бьёт всех** с подходящими метками, включая союзников и носителя. Избирательность — параметр мутации.
- Проверка «действует ли закон на сущность» — одна функция `affects(law, entity)` в `core`, только по меткам.

## Карта (`Grid`)

Сетка клеток (размер клетки — константа, например 32 единицы). У клетки: тип поверхности, температура, влажность, радиация, искажение, след. См. [../09-map.md](../09-map.md). Объекты карты (деревья, камни) — обычные сущности с метками.

## Журнал событий

Каждое изменение состояния записывается: `{ tick, kind, target, cause: { lawId?, sourceId? }, before, after }`. Журнал нужен для:
- отладки и тестов (проверять «что произошло и почему»);
- инструмента `tools/sim`;
- позже — интерфейса «почему я умер».

## Детерминизм

Одинаковые входные данные (начальный мир + сид + команды игроков по тикам) → одинаковый результат. Это нужно для реплеев, тестов и ботов. Правила — в [code-style.md](code-style.md).

## Команды и план действий

Игроки (и боты) не меняют мир напрямую. Они отправляют **команды** (`move`, `useLaw`, `attack`), которые попадают в `plan` сущности. `planSystem` выполняет план, как только сущность может действовать (её `clock.rate > 0` и состояние позволяет). Это и есть механика «запланированных задач» из [../06-time-system.md](../06-time-system.md).
